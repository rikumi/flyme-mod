# Flyme Mod

一个用于 Flyme 定制的 Android/LSPosed 模块。

设置界面使用 Fluix 主题，提供首页分类和二级页面导航。系统 hook 以参考设备的 Flyme 实现为依据。

## 控制中心

- **隐藏农历日期**：默认关闭。隐藏控制中心头部第二行的农历/干支日期，保留系统公历格式与日历点击入口，公历字号按原资源放大 25%，日期与时钟底部对齐并计入时钟的底部边距。适用于独立版和合并版，横竖屏切换及资源刷新后重新应用；不改锁屏与 AOD 日期。切换后重启 SystemUI，实机效果仍需确认。

- **控制中心操作区域放大**：独立版与合并版的操作区均以顶部正中心为基点统一放大 6%，头部保持原有尺寸。合并版通知同步增宽并保持居中；竖屏通知区域按控制中心纵向放大后增加的高度下移，通知文字和高度保持原有尺寸。
- **控制中心磁贴亮色背景**：磁贴、连接卡片、媒体卡片、设备卡片及亮度和音量滑块的背景使用约 10% 不透明度的白色（`#1AFFFFFF`），保留原有形状、文字、图标及滑块进度颜色。
- **控制中心背景压暗**：仅在深色模式下将控制中心背景层改为约 45% 不透明度的黑色（`#73000000`），保留系统模糊与展开/收起动画，头部文字、状态图标及磁贴文字和图标固定为白色。浅色模式使用系统原有背景和前景着色；主题切换时重新判断模式并恢复原背景。
- **控制中心激活态改为白色**：网络/蓝牙等图标的激活圆形衬底、磁贴开启态及亮度/音量进度使用约 88% 不透明度的白色（`#E0FFFFFF`），网络卡片背景及圆形区域之外的文字不受此开关影响；移动数据图标为绿色，亮度、省电模式和手电筒为黄色，屏幕录制为红色，其它磁贴为蓝色；黄色和绿色在 OKLCH 中按各自色相、明度的可达色度归一化，并调整至接近蓝色的视觉饱和度，保留原色相与明度；红、蓝色保持原有颜色参数。彩色图标不透明度为 85%。音量图标保持 60% 不透明度的灰黑色（`#99000000`）。亮度滑块图标仅在实际进度严格超过 15% 时显示黄色，15% 及以下保持白色。此功能同时适用于独立版和合并版，激活态着色优先于磁贴亮色背景和背景压暗的前景着色。
- **自定义背景模糊半径**：默认 20，滑条范围 0–40，实际半径乘以 10。修改整个通控中心背景的 Surface 模糊和根壁纸渲染模糊，覆盖独立版和合并版，保留展开/收起过渡；不改变通知卡片自身的模糊半径。

控制中心的五个开关默认关闭。在 LSPosed 中启用模块并勾选 `com.android.systemui`，修改设置后重启 SystemUI 或设备。首页和二级页面的右上角菜单提供“重启作用域”（SystemUI 和 Flyme 桌面）和“重启 Zygote”，需要 root 授权。模块不自动重启进程。

适配依据为下述参考 APK 的 `ControlCenterPanelView.onLayout(boolean,int,int,int,int)`、`MzQSContainerImpl.setPadding(int)`、`QSTileViewImpl.getBackgroundColorForState(int,boolean)`、`FlymeCustomQSTileView.getBackgroundColorForState(int)`、`MzQSPanel.setWrapperForUiModel(int,int,int,int,int)` 和 `BrightnessSliderView.changeSliderBgColor(int)`。设置保存在设备保护存储中，通过只读 ContentProvider 向 SystemUI 和 Flyme 桌面的实际 UID 提供；每个 SystemUI 进程读取一次。其他 Flyme 版本及实机显示效果仍需验证。

## 通知中心

- **增大通知圆角**：使用控制中心的 `qs_corner_radius`（参考系统为 22dp）更新通知背景与裁剪轮廓，包括播放控制卡片的模糊背景、封面与遮罩；通知内容四周各增加 4dp 内边距，并计入通知测量尺寸。开关位于“通知中心与状态栏 → 通知中心设置”，默认关闭，修改后重启 SystemUI 生效。
- **通知操作按钮改为黑白色**：位于同一页面，默认关闭。标准通知操作按钮及智能操作按钮的文字在浅色模式使用黑色，深色模式使用白色；覆盖内容更新、按钮失效和配置变化时的重新着色，保留不可用状态的淡化效果，不改变按钮背景和图标。修改开关后重启 SystemUI 生效，实机显示效果仍需验证。

增大通知圆角时，通知中心展开内容的测量上限补入新增的上下内边距（共 8dp）；操作区的偏移计算扣除这部分外层内边距，避免按钮被推向卡片下边缘。`getViewHeight` 和 `getExpandHeight` 已包含容器内边距，不再重复增加高度；heads-up 沿用现有测量及操作区偏移。

## 状态栏

恢复后的第三方通知图标以中心为基点缩小到原尺寸的 0.6 倍，保留图标占用的布局间距及通知溢出圆点尺寸。

- **合并双卡信号**：位于“通知中心与状态栏 → 状态栏设置”，默认关闭。存在两个可见的 SIM 卡信号时，第一个信号压缩到 60% 高度并下移整体高度的 12%，第二个信号裁剪保留底部 35%，两排信号的可见区域重叠整体高度的 7%，并合并占用一个信号图标的位置；上传下载箭头从容器左侧向右偏移 3dp，并相对原位置下移 0.5dp。在原信号视图的绘制流程中合成双卡图标，保留两张卡原有的信号状态与着色更新；恢复单卡时使用原有布局。
- **独立显示网络制式**：位于同一页面，默认关闭。按当前活动数据订阅选择网络制式，使用系统 `status_bar_clock_size` 的 90%（参考版本约为 11.7dp）显示在对应信号的左侧；双卡合并时显示在合并图标左侧。隐藏原有小号网络制式图标，沿用原系统的制式显示判断，支持切换默认上网卡及明暗着色更新。原系统判断不显示或当前默认网络为 Wi-Fi 时隐藏制式；满足显示条件后自动恢复。

实现依据为 `FlymeMobileIconBinder.bind`、`CellularIconViewModel` 的网络制式映射及 `StatusIconContainer` 的测量与定位方法。两个开关可独立开启，修改后重启 SystemUI 生效；双卡切换、信号绘制和实机布局仍需验证。

- **恢复原生第三方通知图标**：位于“通知中心与状态栏 → 状态栏设置”，默认关闭。在 `FlymeNotificationIconUtils.resetNotificationSmallIconIfNeed(StatusBarNotification)` 替换资源前保存第三方应用提供的通知小图标，在 `StatusBarIconView.set(StatusBarIcon)` 中使用原图标并清除预加载的替代资源，保留原有明暗着色、缩放和通知更新处理。系统应用及更新后的系统应用使用原有行为；不改写通知卡片的图标数据。修改后重启 SystemUI 生效，实机显示效果仍需验证。

## 桌面文件夹

- **桌面文件夹水平分页**：位于“桌面 → 文件夹”，默认关闭。恢复原有水平分页触摸，每页固定 4 行 3 列，沿用桌面的 `FlymeWorkspaceIndicatorView` 分页控件，非当前页为约 35% 不透明度的白色实心圆点，当前页为不透明白色标记；按页面处理拖动排序、批量拖入与动画图标坐标。展开和关闭动画期间隐藏非当前页，并在动画结束或取消时恢复原可见状态，保留页面的测量位置。
- **桌面文件夹垂直居中**：位于同一页面，默认关闭。按屏幕可用高度计算打开位置，并同步更新展开、关闭的缩放轴与文件夹高度变化动画的目标位置。可独立于水平分页开启。

需要在 LSPosed 中勾选 `com.meizu.flyme.launcher`，修改后重启桌面生效。依据参考 APK 的 `FolderPagedView`、`FolderGridOrganizer`、`MzFolderPagedViewHelper`、`MzFolderHelper` 和 `FlymeFolder` 实现；分页、拖动及动画效果仍需实机验证。

第二页及后续页面关闭时，动画生成过程使用当前页的图标列表，沿用 Flyme 原有的位移、缩放、文字与淡出动画；临时关闭当前页祖先容器的裁剪，并在结束或取消时恢复裁剪及图标变换状态。桌面上的文件夹预览仍使用第一页图标。

分页控件在展开、折叠动画期间隐藏，动画结束或取消后恢复。文件夹收起时直接刷新首页预览，跳过后续页预览滑回首页的动画，避免原预览分页容量与新增水平分页不一致而显示空白。

## 壁纸

- **修复开机时壁纸强制调暗**：位于“桌面 → 壁纸设置”，默认关闭。开启后，`SettingsUpdateMonitor.isAdjustWallpaperDarkEnabled()` 直接读取系统保存的 `flyme_dark_mode_adjust_wallpaper`，避免壁纸引擎在设置监视器初始化前保存默认开启值。保留系统原有默认值、调暗偏好与后续设置回调，不修改系统设置或壁纸图片。模块设置支持首次解锁前读取，修改开关后重启 SystemUI 生效。启动顺序及重启后效果仍需实机验证。

## 首页工具与系统设置

- 控制中心新增“修复合并控制中心二次展开动画”，默认关闭。折叠面板保留独立布局，宽度、水平间距和顶部位置按展开网格对齐，并同步刷新通知起点；逐张比较网络、亮度和音量卡片的实际布局范围，重叠时取消缩放与淡入淡出，不重叠、移到其它行或其它页时保留原生过渡；其余磁贴始终保留过渡，不再固定前两行。二次展开手势由 QS 处理，松手不触发整体头部回弹；已经全部展开后再次下拉，卡片按手指位移的 0.5 倍向下移动，松手后从实际位移回弹。新手势取消旧的回弹动画，向上折叠、分离模式及关闭开关保留原流程。与合并中心开启/关闭动画及位移基准点修复协调，避免两个手势同时控制位移。SystemUI 16260625 的方法及字段已核验；模拟检查覆盖前两行与后续行、二次展开回弹抑制、半速阻尼及松手衔接、旧动画取消和模式旁路，实机效果待验证。

- 控制中心新增“合并控制中心清空通知后保持开启”，默认关闭。合并中心中最后一条通知被清除后隐藏空通知提示，并调用原生 QS 全磁贴展开动画；清空引起的紧邻控制中心关闭请求会被拦截，分离模式和普通空通知状态不改变。

- 控制中心新增“修复控制中心位移基准点”，默认关闭，可独立于合并中心开启/关闭动画修复使用。按当前约定固定补偿 56dp，依屏幕密度换算：展开跟踪时控制中心从正常位置上方 56dp 起步，手指移动 56dp 时位于正常位置，超过后的附加位移采用半速阻尼。收起从当前展开位置跟踪，反向拉回仍支持超过正常位置。松手后由单独的位置动画从实际位移与透明度连续移向展开位置或收起位置，屏蔽重复的原生头部回弹；展开判定使用手指实际下拉距离与系统触摸阈值，不减去 56dp，也不依赖补偿后的视觉位移，取消触摸保留系统判定；开启动画提前结束也不跳到目标位置，新的触摸会取消旧的位置动画。与立即关闭开关同时开启时，本功能保留收起动画。模拟检查覆盖上下两侧归位、56dp 基准及密度换算、提前完成和重复回弹、旧动画取消；构建和签名检查通过，实机效果待验证。

- 合并中心开启/关闭动画修复支持收起手势反向拉回，越过展开位置后，卡片按手指位移的一半向下移动，透明度保持正常。松手未满足系统收起条件时，沿用原生高度回弹，从实际视觉位置恢复展开；超过展开位置后再次收起也保留松手位置衔接。模拟检查覆盖反向跨越、阻尼位移、回弹起点与结束状态；实机效果待验证。
- 反向拉回的位移直接取原生 `TouchHandler.handleTouch` 中当前触摸指针与 `mInitialExpandY` 的差值，不再将完全展开进度换算为手指位移，避免起始帧产生整屏偏移。在合并中心收起手势的跟踪期间，阻止 QS 单独接管二次下拉；分离模式、锁屏及通知筛选页保持原流程。模拟检查覆盖完全展开首帧零位移、30px 下拉对应卡片 15px 位移、真实位移与面板进度不一致、反向跨越和二次展开旁路。构建通过，实机效果待验证。

- 控制中心新增“修复合并控制中心上拉动画起始位置”，默认关闭。SystemUI 16260625 的 `startMzHeightAnimator` 会将收起动画的起点重设为面板高度的 7%，且松手时启动 QS 回弹。开启后，在合并模式的已展开面板中，上拉松手且系统已判定应收起时，改用原生 `instantCollapsePanel` 立即关闭，并取消 QS 回弹、重置位移。开关独立于下拉动画修复；保留分离模式、锁屏、通知筛选页、展开判定和程序触发的关闭流程。参考方法签名、模拟测试及构建检查通过，实机效果待验证。

- 锁屏视觉新增“限制息屏显示移动范围”，默认关闭。依据 SystemUI 16260625 的 `ClockContainerViewBinderData.calculateBurnInOffset` 限制新式时钟横纵偏移为 ±10dp；照片框与个性时钟采用对应锁屏顶部位置，彩色时钟保留带符号的偏移，避免负偏移触发指纹图标的大幅位置调整。旧式 `AODDisplayView` 采用原有初始顶部附近的 ±10dp 偏移，保持原有移动索引与更新时机，水平位置保留原有居中布局。方法及字段已核验；模拟测试验证 40,000 次随机偏移范围、首次位置、旧式布局重复索引一致性、关闭开关和无关调用，以及异常后的状态清理。构建通过，实机各样式效果待验证。

- 控制中心的“修复合并控制中心下拉动画”更名为“修复合并中心开启/关闭动画”，保留原有偏好键。开启时，下拉展开和上拉收起均按手势进度分配控制中心与通知的位移、透明度。合并版原生上拉高度为 `maxHeight * .07 + fingerDelta * .7`，据此计算向上的跟手移动和连续淡出。松手收起时保留当前高度，由原有高度动画继续控制位移与淡出，不再启动向展开位置的 QS 回弹；取消收起时从松手位置与透明度恢复展开。原有“修复合并控制中心上拉动画起始位置”独立开关继续提供松手立即关闭行为。分离模式、锁屏和通知筛选页保留原有逻辑。模拟测试覆盖收起进度、松手连续性、取消后恢复展开和原有展开行为；实机效果待验证。
- 开启/关闭动画修复在 `onHeightUpdated` 面板归零时同步清除手势记录，取消透明度动画及 QS 回弹，将位移与透明度归零；`onExpandingFinished` 对已收起面板补充清理。新手势开始及取得动画控制权时也取消上次未结束的回弹，避免快速收起后重新展开被旧动画覆盖。模拟测试覆盖归零后立即展开、动画清理及关闭开关/分离模式旁路。
- 上拉收起的淡出集中在手势开始后的 24dp 内，按屏幕密度换算；超过该距离后保持完全透明并限制位移，不再继续大幅向上移动。松手继续收起和取消收起恢复展开仍从实际透明度与位移衔接。模拟测试覆盖 24dp 完全淡出、位移上限、不同屏幕密度及松手连续性。
- “控制中心 → 音量调节设置”新增“修改音量调节前四小格”下拉项：默认“不修改”，可选“合并为两中格”（0→2→4）或“合并为一大格”（0→4），降音量使用相反序列，第五级及以上保留原有行为。依据已保存 Flyme framework 的物理键升降标志，在 `VolumePanel.postVolumeChanged` 读取面板状态前校正前四级整数音量；触摸拖动、远程音量、独立应用音量和最小音量非零的通话流不处理。无需增加作用域。逻辑测试覆盖升降方向、模式、第四级边界和非物理键旁路；当前设备未连接，实机按键及显示效果待验证。

- 首页恢复“启动 KernelSU”“启动 LSPosed”和全局“一键启用”，采用 coloros-mod 的并排入口与主开关卡片。任一功能启用时主开关显示“启用模块”；开启时启用全部模块开关并应用推荐系统值，关闭时关闭全部模块开关、将长按超时恢复为 500ms、三项动画倍率恢复为 1。root 操作仅在点击入口、切换开关或结束滑块操作时执行。
